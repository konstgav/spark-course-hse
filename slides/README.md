# Слайды курса

Слайды — это обычный Markdown, который [Marp](https://marp.app/) превращает в
презентацию. PowerPoint не нужен: слайды лежат в git рядом с кодом стенда, нормально
диффятся и показываются прямо из VS Code или из браузера.

## Что здесь лежит

```
slides/
├── README.md                     этот файл
├── theme/
│   ├── course.css                тема курса (фоны, цвета, шрифты)
│   ├── logo-2.svg                логотип ВШЭ для титульного слайда
│   └── logo_new.png              логотип Digital Future Systems
└── 01-intro/
    ├── slides.md                 занятие 1: один файл = одно занятие
    └── img/
        ├── architecture.svg      схема стенда
        └── cover-*.png           обложки книг (первая страница PDF из books/)
```

Одно занятие — один каталог `NN-название/` с файлом `slides.md` и подкаталогом `img/`.
Слайды внутри файла разделяются строкой `---`.

## Как показывать с экрана

### Вариант 1. VS Code (рекомендуется, прав администратора не требует)

1. Поставить расширение **Marp for VS Code** (`marp-team.marp-vscode`) — при открытии
   репозитория VS Code предложит его сам, см. [.vscode/extensions.json](../.vscode/extensions.json).
2. Открыть `slides/01-intro/slides.md` и нажать кнопку предпросмотра справа сверху.
3. Показ: в предпросмотре `...` → **Export slide deck** → `HTML` → открыть файл
   в браузере и нажать `F11`.

Тема курса уже подключена через [.vscode/settings.json](../.vscode/settings.json), поэтому
`theme: course` в начале файла работает без дополнительной настройки.

В экспортированном HTML работает режим докладчика: клавиша `p` открывает отдельное окно
с заметками и таймером — слайды при этом остаются на проекторе.

### Вариант 2. Из командной строки

Нужен Node.js 18+ (ставится и в conda-окружение курса: `conda install -c conda-forge nodejs`).
Команды выполняются из корня репозитория.

```bash
# живой предпросмотр с перезагрузкой при сохранении файла
npx @marp-team/marp-cli@latest --theme-set slides/theme -p -w slides/01-intro/slides.md

# сервер со списком всех занятий: http://localhost:8080
npx @marp-team/marp-cli@latest --theme-set slides/theme -s slides/
```

## Экспорт

PDF, PPTX и PNG рендерятся через браузер, поэтому картинки и логотипы попадают **внутрь**
файла — такой экспорт можно складывать куда угодно:

```bash
# PDF — раздать студентам или показывать без Marp
npx @marp-team/marp-cli@latest --theme-set slides/theme --allow-local-files \
    --pdf -o slides/build/01-intro.pdf slides/01-intro/slides.md

# PNG по слайду — быстро проверить вёрстку и переполнение слайдов
npx @marp-team/marp-cli@latest --theme-set slides/theme --allow-local-files \
    --images png -o slides/build/01-intro.png slides/01-intro/slides.md
```

HTML ведёт себя иначе: **Marp не встраивает картинки в HTML**, а оставляет относительные
пути (`img/architecture.svg`, `../theme/logo_new.png`) — они считаются от каталога `slides.md`.
Поэтому HTML нужно складывать **рядом с `slides.md`**, иначе слайды откроются без схемы
и логотипов:

```bash
# правильно: HTML лежит там же, где slides.md
npx @marp-team/marp-cli@latest --theme-set slides/theme \
    --html -o slides/01-intro/deck.html slides/01-intro/slides.md

# сломается: из slides/build/ пути к картинкам не разрешатся
#   --html -o slides/build/01-intro.html
```

Для показа с экрана этого достаточно: `deck.html` открывается в браузере, `F11` — полный
экран. Если HTML нужно отправить одним файлом, отправляйте PDF.

`slides/build/`, а также любые `*.html`, `*.pdf` и `*.pptx` внутри `slides/` исключены из
git: в репозитории хранятся только исходники. `--allow-local-files` нужен потому, что
рендеринг читает локальные картинки и логотипы.

Для PDF, PPTX и PNG требуется браузер на Chromium — на Windows подходит предустановленный
Edge, отдельно ничего ставить не нужно. Если он не находится автоматически, укажите путь
переменной `CHROME_PATH`.

## Типы слайдов

Тип задаётся директивой в HTML-комментарии на самом слайде. Подчёркивание в `_class`
означает «только этот слайд»; без подчёркивания — все последующие.

| Директива | Фон | Для чего |
|---|---|---|
| `<!-- _class: title -->` | светлый градиент, логотипы | титульный слайд занятия |
| `<!-- _class: book -->` | светло-голубой, обложка слева | рекомендованная литература |
| `<!-- _class: lead -->` | почти белый, синяя полоса слева | разделитель между блоками |
| `<!-- _class: theory -->` | **светло-голубой** | теория, объяснения, схемы |
| `<!-- _class: practice -->` | **светло-розовый** | то, что студенты делают сами |
| без директивы | белый | план, итоги, вопросы |

Цвет фона — это навигация для аудитории: розовый слайд означает «ноутбук открыт, делаем».
Поэтому не смешивайте на одном слайде объяснение и задание — разделите на два.

На слайдах `practice` нумерованный список автоматически превращается в шаги с красными
кружками, поэтому шаги задания пишутся обычным `1.` / `2.` / `3.`.

Слайд `book` строится на split-фоне Marp: обложка задаётся первой строкой слайда как
`![bg left:34% fit](img/cover-название.png)`, дальше идут заголовок, строка с авторами
курсивом и аннотация. Обложки берутся из PDF в [books/](../books/) первой страницей:

```bash
pdftoppm -f 1 -l 1 -r 100 -png "books/Название.pdf" slides/01-intro/img/cover-название
```

## Как добавить слайд к занятию

Дописать в конец `slides.md` разделитель и новый слайд:

```markdown
---

<!-- _class: theory -->

## Заголовок слайда

* тезис
* тезис
```

Так добавление слайда — это диff в несколько строк в конце файла, а не правка бинарника,
и два человека могут готовить разные занятия без конфликтов.

> **Перенос строки в исходнике = перенос строки на слайде.** Marp включает режим
> `breaks`, поэтому абзац переносится ровно так, как он набран в `.md`. Это удобно для
> команд внутри шага задания (каждая на своей строке), но абзац обычного текста лучше
> набирать так, чтобы разрывы попадали в осмысленные места.

## Как добавить занятие

```bash
mkdir -p slides/02-metadata/img
cp slides/01-intro/slides.md slides/02-metadata/slides.md   # титульный слайд как шаблон
```

Дальше поправить в титульном слайде номер и тему занятия и писать содержание.

## Тема курса

[theme/course.css](theme/course.css) — единственное место, где заданы цвета и шрифты.
Палитра собрана из двух логотипов на титульном слайде:

* `#0F2D69` — синий ВШЭ → теория, заголовки, схемы
* `#C0272D` — красный Digital Future Systems → практика, задания

Все фоны светлые: слайды рассчитаны на проектор в освещённой аудитории, где тёмные темы
теряют контраст. Шрифты берутся системные (Segoe UI на Windows, Noto Sans / PT Sans на
Linux), поэтому слайды открываются одинаково и без интернета.

Логотипы лежат рядом с темой, в `theme/`, и подключаются с титульного слайда как
`../theme/logo-2.svg` и `../theme/logo_new.png` — по одной копии на весь курс, поэтому замена
файла меняет титульные слайды всех занятий сразу.
